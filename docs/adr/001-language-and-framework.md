# ADR-001: Выбор языка программирования и фреймворка

| Поле | Значение |
|---|---|
| Статус | Accepted |
| Дата | 2026-09-30 |
| Автор | Тетюшкин Н.Д. |

## Контекст

Проект — Telegram-бот для учёта личных расходов (ExpenseBot). Пользователь отправляет сообщение вида «250 кофе», бот сохраняет расход и по команде показывает отчёт по категориям за месяц. Подробные требования описаны в `docs/prd.md`.

Ограничения проекта:

- Разработчик один, это учебный проект; срок — 8 недель.
- Основной язык, которым владеет автор, — Python; есть базовый опыт с JavaScript.
- Бот должен работать на недорогом VPS с 512 МБ памяти, без сложной инфраструктуры.
- Нагрузка небольшая: десятки пользователей, единицы сообщений в минуту. Узким местом будут сетевые запросы к Telegram, а не вычисления.
- По заданию курса нужны линтер, форматтер, проверка типов и генерация документации из docstrings.

## Рассмотренные альтернативы

1. **Python + aiogram 3** — асинхронная библиотека для Telegram Bot API.
2. **Python + python-telegram-bot** — популярная библиотека, в версии 20+ тоже асинхронная.
3. **Node.js + Telegraf** — JavaScript-фреймворк для Telegram-ботов.
4. **Go + telebot** — компилируемый язык с высокой производительностью.

## Решение

Python 3.11+ и фреймворк **aiogram 3**.

## Обоснование

- Python — основной язык автора, поэтому не нужно тратить время на изучение нового языка; срок 8 недель для этого слишком мал.
- aiogram 3 изначально асинхронный, имеет встроенный роутер обработчиков, фильтры и конечные автоматы состояний (FSM). Это упрощает дальнейшее добавление диалоговых сценариев (например, задание лимита).
- Экосистема Python закрывает требования курса: flake8 и black для стиля, mypy для типов, Sphinx и MkDocs для документации, pytest для тестов.
- python-telegram-bot тоже подходил бы, но aiogram лучше документирован для асинхронного стиля, а его API для фильтров и роутеров компактнее. Отдельной сложностью стало бы смешение синхронного и асинхронного кода в старых примерах python-telegram-bot.
- Node.js + Telegraf потребовал бы перехода на TypeScript ради проверки типов и изучения нового инструментария сборки, что увеличивает риск не уложиться в срок.
- Go даёт лучшую производительность, но при нашей нагрузке это преимущество не нужно, а порог входа и время разработки выше.

## Последствия

**Плюсы**

- Быстрая разработка на знакомом языке.
- Хорошая поддержка типизации и автодокументации из docstrings.
- Асинхронная обработка позволяет обслуживать много пользователей в одном процессе.
- Богатая экосистема библиотек и тестовых инструментов.

**Минусы**

- Python медленнее Go и потребляет больше памяти; при росте до тысяч активных пользователей может потребоваться оптимизация или масштабирование.
- GIL ограничивает CPU-bound задачи; если появятся тяжёлые вычисления (например, аналитика по большим периодам), их придётся выносить в отдельные процессы.
- aiogram 3 менее распространён, чем python-telegram-bot, поэтому по нему меньше ответов на сторонних форумах, и часть материалов устарела (относится к версии 2).
- Проект привязан к Telegram Bot API; смена мессенджера потребует переписать слой обработчиков (бизнес-логика от него отделена, см. ADR-003).
