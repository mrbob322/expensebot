## 1. Overview

**ExpenseBot** — Telegram-бот, который позволяет записывать личные расходы одним сообщением (например, `250 кофе`) и получать отчёт по категориям за месяц.

**Для кого:** студенты и молодые специалисты, которые хотят контролировать бюджет, но не хотят устанавливать отдельное приложение и заполнять длинные формы.

**Проблема:** существующие приложения для учёта финансов перегружены функциями, требуют регистрации и долгого ввода. В результате люди бросают вести учёт через 1–2 недели.

## 2. Goals and Non-Goals

### Goals

- Добавление расхода одним текстовым сообщением за ≤ 5 секунд.
- Отчёт по категориям за текущий месяц.
- Хранение данных каждого пользователя отдельно.
- Простая установка и запуск (одна команда).

### Non-Goals

- Интеграция с банками и автоматический импорт операций.
- Учёт доходов и инвестиций.
- Многопользовательские (семейные) бюджеты.
- Мобильное или веб-приложение.
- Мультивалютность в версии 0.1.0.

## 3. User Personas

### Персона 1. Аня, студентка, 19 лет

- **Цели:** укладываться в стипендию и деньги от родителей; понимать, куда уходят деньги.
- **Боли:** забывает записывать траты вечером; приложения слишком сложные.
- **Сценарий:** после покупки в столовой пишет боту `180 еда обед`, в конце недели запрашивает отчёт.

### Персона 2. Максим, джуниор-разработчик, 24 года

- **Цели:** копить на переезд, видеть крупные статьи расходов.
- **Боли:** не хочет доверять данные сторонним сервисам; нужен быстрый ввод без лишних кликов.
- **Сценарий:** записывает траты в течение дня, в конце месяца смотрит отчёт и сравнивает категории.

## 5. Functional Requirements

| ID | Требование | Проверка |
|---|---|---|
| FR-001 | Бот отвечает на команду `/start` приветствием и описанием формата ввода. | Ручная / e2e |
| FR-002 | Бот принимает сообщение формата `<сумма> <категория> [комментарий]` и сохраняет расход с текущей датой. | Unit |
| FR-003 | Сумма принимается с разделителем «.» или «,» и не более чем с двумя знаками после него. | Unit |
| FR-004 | Категория приводится к нижнему регистру. | Unit |
| FR-005 | При неверном формате или сумме ≤ 0 бот возвращает понятное сообщение об ошибке, запись не создаётся. | Unit |
| FR-006 | Команда `/report` возвращает суммы по категориям с начала текущего месяца по сегодня. | Integration |
| FR-007 | Данные хранятся раздельно по `user_id`; пользователь видит только свои расходы. | Integration |
| FR-008 | Сумма хранится в копейках (целое число) без потери точности. | Unit |
| FR-009 | Команда `/last` показывает 10 последних расходов пользователя. | Integration |
| FR-010 | Команда `/undo` удаляет последнюю запись пользователя. | Integration |

## 6. Non-Functional Requirements

| Категория | Требование |
|---|---|
| Производительность | Ответ на сообщение — не более 1 с (p95) при 100 пользователях. |
| Надёжность | Данные сохраняются в БД до отправки подтверждения пользователю; при перезапуске бота записи не теряются. |
| Безопасность | Токен бота хранится в переменной окружения, не в репозитории; все SQL-запросы параметризованы. |
| Масштабируемость | Слой хранения изолирован (ADR-003), чтобы заменить SQLite на PostgreSQL без изменения бизнес-логики. |
| Удобство | Ввод расхода — одно сообщение; сообщения об ошибках на русском языке. |
| Сопровождаемость | Код проходит flake8, black и mypy (strict); покрытие тестами не менее 70%. |

## 7. Success Metrics

- **Активация:** ≥ 70% пользователей записывают первый расход в течение суток после `/start`.
- **Retention D7:** ≥ 30% пользователей возвращаются на 7-й день.
- **WAU:** не менее 20 активных пользователей в неделю через месяц после запуска.
- **Latency p95:** ≤ 1 с на обработку сообщения.
- **Доля ошибок ввода:** ≤ 10% сообщений завершаются сообщением о неверном формате.

## 9. Open Questions

| Вопрос | Когда и как решим |
|---|---|
| Нужен ли фиксированный список категорий или пользователь вводит любые? | До v0.2.0: опрос 5–10 пользователей MVP. |
| Где хостить бот (VPS, Railway, домашний сервер)? | До релиза v1.0.0: сравнить по цене и стабильности. |
| Когда переходить с SQLite на PostgreSQL? | При превышении 100 активных пользователей или при росте задержки p95 выше 1 с. |
| Нужна ли поддержка других валют? | После релиза v1.0.0, по запросам пользователей. |
